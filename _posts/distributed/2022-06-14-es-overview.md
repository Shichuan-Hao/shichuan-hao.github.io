> ElasticSearch 简称 ES，是一个用 Java 开发的开源分布式搜索和数据分析引擎，当前最流行的企业级搜索引擎，能够达到近实时搜索。

---

## 一、什么是 ElasticSearch

ES 是一个开源的分布式搜索和数据分析引擎，专门设计用于处理大规模的文本数据和实现高性能的全文检索。

在搜索引擎排名中，ES 排名第一：
- 参考网站：`https://db-engines.com/en/ranking/search+engine`
- 官方网站：`https://www.elastic.co/`
- 下载地址：`https://www.elastic.co/cn/downloads/past-releases#elasticsearch`

### ES 的核心优势

| 优势 | 说明 |
|------|------|
| **分布式架构** | 轻松处理大规模数据，支持水平扩展，提高可扩展性和容错性 |
| **全文检索功能** | 强大的全文检索，支持复杂查询语法和自定义分析器 |
| **多语言支持** | 支持多种语言的数据处理和检索 |
| **高性能** | 基于倒排索引等优化技术，满足大规模数据实时查询 |
| **实时性** | 近乎实时的搜索和分析功能 |
| **易用性** | 丰富的 API 和插件，RESTful 接口 |

## 二、Elastic Stack 生态介绍

Elastic Stack 由四大核心产品组成：

```
┌──────────────────────────────────────────────┐
│                  Kibana                        │
│           (可视化和管理界面)                     │
├──────────────────────────────────────────────┤
│              Elasticsearch                     │
│     (全文搜索与分析引擎，Elastic Stack 基石)      │
├──────────────────────────────────────────────┤
│               Logstash                         │
│        (服务端数据处理管道)                      │
├──────────────────────────────────────────────┤
│                Beats                           │
│    (轻量级数据采集器：Filebeat/Metricbeat等)      │
└──────────────────────────────────────────────┘
```

**各组件职责**：

- **Elasticsearch**：Elastic Stack 的基石。高度可扩展的开源全文搜索与分析引擎，利用分布式架构提供近乎实时的数据搜索、分析和可视化能力。

- **Logstash**：灵活的服务器端数据处理管道，从多个源采集数据、转换数据、发送到指定目的地。支持丰富的插件生态系统。

- **Beats**：轻量级数据采集器家族，专为发送数据到 Logstash、Elasticsearch 或 Kafka 而设计。包括 Filebeat（文件日志）、Metricbeat（系统和应用指标）、Heartbeat（服务可用性监控）等。

- **Kibana**：Elastic Stack 的可视化和管理界面，可创建仪表板、图表和地图，提供交互式查询和过滤功能。

## 三、ES 应用场景

### 1、全文检索

各类应用、网站等的全文搜索：
- **电商平台**：淘宝、京东的商品搜索
- **应用市场**：360手机助手、豌豆荚的 APP 搜索
- **文档平台**：腾讯文档、石墨文档的全文检索

支持自定义打分、自定义排序、高亮等机制。知名企业包括阿里巴巴、腾讯、携程、滴滴、美团、字节跳动、贝壳找房等都在使用 ES。

### 2、日志分析

ES 支持各种类型的日志：

| 日志类型 | 示例 |
|----------|------|
| 业务日志 | 用户行为日志、应用日志 |
| 状态日志 | 慢查询、异常探测 |
| 系统日志 | Debug、Info、WARN、ERROR、FATAL 等级 |

58集团、唯品会、日志易、国投瑞银等都使用 ES 实时监控和故障排查。

### 3、商业智能场景

大型业务数据的挑战：数据收集和分析。ES 的全文数据检索和聚合分析能力，能帮助企业进行高效个性化分析，发现问题，挖掘商业价值。睿思BI、百度 Sugar BI、永洪BI 等都借助 ES 的能力。

## 四、全文检索 vs 传统查询

### 什么是全文检索

**全文检索**（Full-Text Search）是一种从大量文本数据中快速检索出包含指定词汇或短语的信息的技术。

| | 传统数据库查询 | 全文检索 |
|------|----------------|----------|
| 方式 | `LIKE "%关键词%"` | 倒排索引 |
| 效率 | 遍历所有记录，低效 | 索引直接定位，高效 |
| 结果 | 精确匹配 | 相关性排序 |
| 搜索边界 | 有明确条件边界 | 无搜索条件边界 |
| 召回依据 | 精确匹配 | 相关性计算（同义词、谐音、错别字等） |

**示例对比**：

```sql
-- MySQL：搜索"Java设计模式"
SELECT * FROM t_blog WHERE content LIKE "%Java设计模式%";
-- 问题：遍历所有记录匹配，效率低，结果不符合搜索期望
```

## 五、倒排索引详解

### 正排索引 vs 倒排索引

**正排索引**（Forward Index）：
- 文档按顺序排列编号
- 每个文档包含完整文本内容和属性
- 适合对文档整体检索和展示
- MySQL 通过 ID 查找就是正排索引应用

**倒排索引**（Inverted Index）：
- 根据单词/短语建立索引结构
- 将每个单词映射到包含该单词的文档列表

```
正排索引：
  文档1 → {"Java", "设计模式", "多线程"}
  文档2 → {"设计模式", "JavaScript"}

倒排索引：
  "Java"        → [1]
  "设计模式"     → [1, 2, 3, 4]
  "多线程"      → [2]
  "JavaScript"  → [4]
```

**搜索"Java设计模式"**：先查"Java"→[1]，再查"设计模式"→[1,2,3,4]，取交集 → 文档1 得分最高。

### 倒排索引实现步骤

1. **文档预处理**：分词、移除停用词、词干提取
2. **构建词典**：将词汇添加到词典，分配唯一 ID
3. **创建倒排列表**：记录每个词在哪些文档中出现及位置
4. **存储索引文件**：存储在磁盘上索引文件中（通常压缩处理）
5. **查询处理**：从词典查找关键词对应倒排列表，定位文档

## 六、ES 核心概念（MySQL 对照）

| MySQL | Elasticsearch | 说明 |
|-------|---------------|------|
| Database | Index（索引） | 逻辑容器，存储管理相关数据 |
| Table | Type（已废弃） | 7.x起一个索引只能包含一个文档类型 |
| Row | Document（文档） | JSON 格式的基本存储单元，键值对构成 |
| Column | Field（字段） | 文档中的键 |
| Schema | Mapping（映射） | 类似表结构：字段名称、类型、分词/索引/存储设置 |
| SQL | Query DSL | REST API 传递 JSON 请求体 |

> **注意**：ES 6.X 之前一个索引可有多个 type；ES 7.x 起 type 被弃用；索引名称必须全部小写。

## 七、ES 典型 Mapping 示例

```json
PUT /employee
{
  "mappings": {
    "properties": {
      "name": {
        "type": "keyword"
      },
      "sex": {
        "type": "integer"
      },
      "age": {
        "type": "integer"
      },
      "address": {
        "type": "text",
        "analyzer": "ik_max_word"
      },
      "remark": {
        "type": "text",
        "analyzer": "ik_smart"
      }
    }
  }
}
```

**字段类型核心对比**：

| 类型 | 说明 | 是否分词 | 常见场景 |
|------|------|----------|----------|
| `text` | 全文本，会分词 | ✅ | 文章内容、描述 |
| `keyword` | 精确值，不分词 | ❌ | 标签、状态、邮箱 |
| `integer` / `long` | 整数 | ❌ | 年龄、数量 |
| `date` | 日期 | ❌ | 创建/更新时间 |
| `boolean` | 布尔值 | ❌ | 是否删除 |

**文档元数据**：

```json
{
  "_index": "employee",   // 所属索引
  "_id": "1",             // 文档唯一标识
  "_source": { ... }      // 原始 JSON 数据
}
```

## 八、总结

ElasticSearch 的定位：

```
只要用到搜索的场景，Elasticsearch 几乎都可以是最好的选择。
结合 Kibana、Logstash、Beats，可用于：
  ✓ 全文检索
  ✓ 日志分析
  ✓ 商业智能
```

**为什么选择 ES**：基于倒排索引的全文检索能力 + 分布式架构的处理能力 + Elastic Stack 生态的完善工具链，三者合一。
