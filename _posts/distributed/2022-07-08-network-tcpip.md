## 一、OSI 七层模型 vs TCP/IP 模型

| OSI 七层 | TCP/IP 四层 | 协议 | 设备 |
|----------|------------|------|------|
| 应用层 | 应用层 | HTTP/DNS/FTP/SMTP | |
| 表示层 | ↑ | | |
| 会话层 | ↑ | | |
| 传输层 | 传输层 | **TCP/UDP** | |
| 网络层 | 网络层 | **IP/ICMP/ARP** | 路由器 |
| 数据链路层 | 网络接口层 | Ethernet | 交换机/网桥 |
| 物理层 | ↑ | | 网卡/网线/光纤 |

> 通俗理解：物理层=网卡，数据链路层=网卡驱动，网络层+传输层=操作系统处理，应用层=应用程序。TCP/IP 胜出于 OSI 的原因：更早制定了可行协议+持续改良。

## 二、TCP 协议核心

### TCP 是什么

**TCP（Transmission Control Protocol）**：面向连接的、可靠的、基于字节流的传输层通信协议。

### TCP 可靠性保证机制

| 机制 | 说明 |
|------|------|
| **确认应答** | 每个数据包都需确认（ACK） |
| **超时重传** | 超时未确认则重发 |
| **滑动窗口** | 流量控制，接收方告知发送方可接收多少数据 |
| **拥塞控制** | 慢启动、拥塞避免、快重传、快恢复 |
| **校验和** | 检测数据在传输中的错误 |

### TCP vs UDP

| | TCP | UDP |
|------|-----|-----|
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 可靠传输 | 不保证可靠性 |
| 顺序 | 保证顺序 | 不保证顺序 |
| 速度 | 较慢 | 快 |
| 适用场景 | HTTP/文件传输/邮件 | 视频直播/语音通话/DNS |
| 类比 | 打电话 | 发短信/广播 |

## 三、TCP 三次握手

```
Client                              Server
  │                                    │
  │──── SYN, seq=x ────────────────▶  │  (1)
  │                                    │
  │◀─── SYN+ACK, seq=y, ack=x+1 ────│  (2)
  │                                    │
  │──── ACK, seq=x+1, ack=y+1 ─────▶│  (3)
  │                                    │
  └──── 连接建立，开始传输数据 ────────┘
```

**为什么是三次不是两次？**
防止已失效的连接请求报文突然传到服务端，造成资源浪费。

**为什么不是四次？**
服务端 SYN 和 ACK 可以在一次通信中合并发送。

## 四、TCP 四次挥手

```
Client                              Server
  │                                    │
  │──── FIN, seq=u ────────────────▶  │  (1) Client不再发送数据
  │◀─── ACK, seq=v, ack=u+1 ───────│  (2)
  │                                    │
  │◀─── FIN, seq=w, ack=u+1 ───────│  (3) Server也可以关闭了
  │──── ACK, seq=u+1, ack=w+1 ─────▶│  (4)
  │                                    │
  │  等待 2MSL（最大报文生存时间）       │
  │  确保 Server 收到最后的 ACK         │
  └──── 连接关闭 ─────────────────────┘
```

**为什么是四次不是三次？**
TCP 是全双工的。Client 发送 FIN 只表示自己不发了，Server 可能还有数据需要发送。所以 Server 的 ACK 和 FIN 分开发送。

**为什么 Client 要等待 2MSL？**
确保最后一个 ACK 被 Server 收到。如果丢失，Server 会重发 FIN，Client 可以在 2MSL 内重新响应。

---

## 五、滑动窗口

**为什么需要滑动窗口**：如果每个数据包都要等 ACK 才能发下一个，效率太低。

```
发送方窗口 [1 2 3 | 4 5 6 | 7 8 9]
          已确认  已发送未确认  可发送

接收方窗口 [1 2 3 | 4 5 6]
          已接收  缓存空间
```

**窗口大小**：接收方在 ACK 中告知自己还能接收多少数据，发送方据此调节。

## 六、面试常见问题

### 1. 浏览器输入 URL 发生了什么？（简化版）

```
DNS解析 → TCP三次握手 → HTTP请求 → 服务器处理 → HTTP响应 → 浏览器渲染 → 四次挥手
```

### 2. TCP 是如何保证可靠性的？

确认应答 + 超时重传 + 滑动窗口 + 拥塞控制 + 校验和

### 3. TIME_WAIT 状态的作用？

确保最后的 ACK 被对方收到；让旧连接的残留数据在网络中消失。

## 七、总结

```
网络分层：
  应用层(HTTP) → 传输层(TCP/UDP) → 网络层(IP) → 链路层(Ethernet)

TCP 核心：
  三次握手(建立) + 数据传输(滑动窗口) + 四次挥手(关闭)
  可靠性 = ACK + 重传 + 窗口 + 拥塞控制

UDP：
  无连接 + 不保证可靠 + 快 → 适合实时音视频
```
